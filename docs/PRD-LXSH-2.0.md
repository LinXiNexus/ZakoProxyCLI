# LXSH 重构需求文档（PRD）

- **项目代号**：LXSH（原 ZAKO Relay）
- **文档版本**：v0.1（草案）
- **基线版本**：v1.3.14（Rust + WebView 混合架构）
- **目标版本**：v2.0（原生 Android 重构版）
- **日期**：2026-10-24

---

## 0. 背景与总体目标

当前应用为 Rust（axum，编译为 `liblxshai.so`）+ HTML/React WebView 的混合架构，在移动端存在渲染性能瓶颈（毛玻璃重绘、滚动掉帧）、原生能力受限（文件选择器需补丁、无终端环境），且双技术栈维护成本高。

本次重构以**标准 Android Java 原生项目**重写客户端，禁止继续沿用 Rust + HTML 的写法；同时围绕"AI 智能体 + Shell 工作流"的核心场景，补充临时脚本工作区、流式输出优化、并行工具调用、rm 防护、内置终端等功能。

### 总体原则
1. **数据兼容**：重构后首启必须能无损读取现有 `zako.db`（账号/密钥/分组/破甲策略配置），登录态除外（cookie 名已变，允许重新登录）。
2. **功能对齐**：v1.3.x 的既有功能（中转代理、分组管理、调用日志、破甲策略、个性化、深色模式）在 v2.0 不允许缺失。
3. **UI 一致性**：延续现有视觉语言——iOS 风格毛玻璃、全圆角面板、LXSH 品牌绿、浅色/深色/跟随系统三档主题、四套背景主题 + 自定义背景图。
4. **性能底线**：侧边栏弹出、列表滚动、对话流式渲染在 60Hz 设备满帧；对 90/120/185Hz 高刷设备开放高帧率渲染。

## 1. 需求一：原生 Android Java 重写（P0 · 架构）

### 1.1 技术选型
| 项 | 决策 | 说明 |
|---|---|---|
| 语言 | Java（要求明确禁止 Kotlin 也未提，按"Java 为主"执行；如遇 Jetpack Compose 强依赖 Kotlin 的场景，需单独评审）| 现有 `mobile/src/com/zako/relay` 已是 Java，可直接演进 |
| 最低 SDK | 26（Android 8.0）| 覆盖 termux 类设备主流；WebView 壳时代 minSdk 24 → 26 可淘汰部分兼容代码 |
| 目标 SDK | 35 | 满足 Play 上架基线；侧载不受影响 |
| UI 框架 | 原生 View 体系 + Material Components（XML 布局为主）| 拒绝 WebView/HTML 渲染界面 |
| 架构 | 单 Activity 多 Fragment + ViewModel + Room（或直接复用 SQLite）| |
| 网络 | OkHttp + SSE（自定义 EventSource）| 对话流式输出依赖 |
| 后端 | **保留 Rust 二进制**作为本地代理服务（`liblxshai.so`，前台服务拉起）| 原生 UI ↔ 本地 127.0.0.1:1990 HTTP API 通信；禁止的是"用 HTML 写界面"，代理核心不动 |

### 1.2 范围界定（重要澄清）
> 用户原意："以标准 Android JAVA APP 项目重写，该项目禁止服用(复用) Rust 加 HTML 写法"

落地解释：
- **禁止**：UI 层继续用 HTML/React/WebView 渲染。
- **保留**：Rust 代理内核（`lxshai-proxy`）作为 so 继续提供本地 HTTP API——重写它的成本与收益不匹配（26+ 个集成测试、SSE 转发、账号调度、破甲注入都在里面）。Java 层通过 `http://127.0.0.1:1990` 调用。
- 若用户要求"连内核也纯 Java"，工作量约 +6~8 周，需另行确认。

### 1.3 迁移与兼容
- **包名**：`com.zako.relay` 保持不变（升级安装不丢数据）。
- **数据**：Rust 侧 `zako.db` 原样保留；Java 侧新增的本地偏好（终端配置、按键区布局）存 SharedPreferences/新表。
- **首启流程**：Native UI 检测本地服务健康 → 沿用 `/health` + 管理员登录 API。
- **产物**：`LXSH-debug.apk`（沿用现有签名密钥），versionCode 从 20000 起。

### 1.4 模块划分
```
app/
 ├─ ui/            Fragment + ViewModel + 自定义 View
 │   ├─ home/      仪表盘
 │   ├─ chat/      对话（流式）
 │   ├─ scripts/   临时按键区
 │   ├─ terminal/  内置终端
 │   ├─ settings/  设置中心（二级页面聚合）
 │   └─ common/    毛玻璃背景、圆角面板等主题组件
 ├─ core/          本地服务管理（启动/健康检查/日志）
 ├─ data/          OkHttp API client、SSE、Room/SharedPreferences
 └─ service/       前台服务（拉起 liblxshai.so、常驻通知）
```

## 2. 需求二：临时脚本工作映射区（P1 · 新功能）

### 2.1 概述
侧边栏新增"**临时按键区**"入口。该区域是**由 AI 生成的脚本选项 + 用户手动收藏的 shell 命令**汇总成的可个性化 UI 面板。

### 2.2 功能点
| # | 功能 | 说明 |
|---|---|---|
| 1 | 命令卡片 | 每条收藏 = 一张圆角卡片：图标（可选）、名称、命令摘要、执行按钮 |
| 2 | AI 生成入口 | 对话中 AI 输出的代码块/命令，消息长按或工具条出现"**加入临时按键区**"；AI 主动调 tool 产出脚本时同样可收藏 |
| 3 | 手动添加 | "+ 新建"表单：名称、shell 命令（多行）、图标（预设 12 个）、颜色标签 |
| 4 | 执行与回显 | 点击卡片 → 在**内置终端**（见需求六）中执行，实时回显输出；执行完显示退出码 |
| 5 | 分组/排序 | 长按拖拽排序；支持文件夹分组（如"备份"、"网络"、"清理"）|
| 6 | 变量占位符 | 命令支持 `{{var}}` 占位，执行时弹出填值对话框（如 `{{ip}}`）|
| 7 | 危险标记 | 含 `rm/mkfs/dd/格式化` 字样的命令卡片红色描边 + 二次确认（联动需求五的 rm 拦截）|
| 8 | 导入导出 | JSON 格式导入导出，便于备份与分享 |

### 2.3 数据模型（草案）
```json
{
  "id": "uuid",
  "name": "清理应用缓存",
  "command": "pm trim-cache 999999999",
  "icon": "broom",
  "color": "green",
  "group": "清理",
  "vars": [{"key":"ip","label":"目标IP","default":""}],
  "source": "manual | ai",
  "created_at": 1790000000,
  "run_count": 3
}
```

### 2.4 UI 要求
- 卡片网格 2 列（横屏 3-4 列），延续毛玻璃 + 圆角 + 深色模式适配。
- 空状态引导："让 AI 帮你写一个试试 →"（跳转对话页）。

## 3. 需求三：对话流式输出优化 + 工具调用折叠（P0 · 体验）

### 3.1 实时流式显示
| 项 | 要求 |
|---|---|
| SSE 渲染 | 后端 `delta` 事件到达即追加渲染；**禁止**整段缓冲后一次性刷新 |
| 渲染节流 | 每 ~50ms 批量 append 一次（避免每 token 一次 UI 重排）；保持光标自动滚动到底（用户上滑时暂停跟随，出现"回到底部"悬浮按钮）|
| 打字光标 | 流式期间末尾显示呼吸光标 `▌`；`done` 事件后移除 |
| 失败恢复 | 流中断时保留已收文本 + 行内错误条（可重试，从断点续传由后端决定）|
| Markdown | 流式期间以纯文本增量渲染；`done` 后一次性格式化（代码高亮、表格）|

### 3.2 非流式输出的"实时非流式"体验
- 非流式请求：发出后立即显示"生成中"占位气泡（含动画），响应返回后**打字机式渐进显示**（速度 ~2000 字符/秒，可整体点击跳过），而非突然整段弹出。

### 3.3 连续工具调用折叠
| 场景 | 表现 |
|---|---|
| AI 连续调用 ≥2 个工具 | 工具条目自动折叠为一行摘要：`⚙ 已执行 3 个工具 · 12.4s ▸` 点击展开明细 |
| 单工具调用 | 正常显示单条（名称 + 参数摘要 + 耗时 + 状态点）|
| 工具执行中 | 折叠头显示进行中 spinner 与当前工具名 |
| 失败工具 | 折叠头红色状态点 + 展开可见错误；不受"默认折叠"影响，单独保持展开 |
| 用户偏好 | 个性化新增开关："连续工具调用自动折叠"（默认开）+ "思考过程默认展开"沿用 |

## 4. 需求四：并行多工具调用（P1 · 能力）

### 4.1 目标
允许 AI 在**单次响应**中声明多个工具调用，Agent **并行执行**（多线程），全部完成后统一回传结果继续对话。

### 4.2 协议与实现要点
| 层 | 改动 |
|---|---|
| Rust agent（`src/agent.rs`）| 解析 `tool_calls` 数组（当前只取首个）；为每个 call 创建任务；无依赖的工具并行 `tokio::spawn`；有依赖（如写文件后执行）按 AI 声明的顺序号串行 |
| 并发上限 | 同时执行工具数默认 4，设置中可调（1-8）|
| 结果聚合 | 每个工具完成即推送 SSE 事件 `tool_result`（带 call_id），UI 增量显示；全部 done 后进入下一轮 |
| 超时 | 单工具超时 60s（可配置），超时按失败回传 |
| 失败隔离 | 单个工具失败不影响其他并行工具；失败信息作为 tool result 回给模型自行决策 |

### 4.3 UI 呈现
- 并行执行时折叠头显示 `⚙ 并行执行 3 个工具（2 完成 1 进行中）`，展开可见每条独立进度。
- 前端（Java）按 call_id 维护工具条目状态机：pending → running → done/failed。

### 4.4 兼容
- 上游模型不支持多 tool_calls 时自动退化为串行，行为与现状一致。

## 5. 需求五：rm 指令拦截与安全回收站（P0 · 安全）

### 5.1 规则（"2m 指令拦截"落地解释）
> 用户原意："新增 2m 指令拦截，当 AI 执行 rm 指令时，agent 执行的实际命令应当是移动……自定义的一个目录，并且在用户能访问的地方"

即：**AI 的 rm 不真正删除，而是移动（move）到自定义安全目录**——"2m" 理解为 "to move"（rm → mv 重写）。

### 5.2 行为定义
| 项 | 定义 |
|---|---|
| 拦截范围 | Agent 工具执行的所有 shell 命令中出现的 `rm`/`rm -rf`/`unlink`；含子 shell、管道中的 rm |
| 重写规则 | `rm [opts] PATH...` → `mv PATH... <回收目录>/<时间戳>/原文件名`（同名冲突自动追加 `.1`、`.2`）|
| 回收目录 | 默认 `/sdcard/LXSH/trash/`（用户可见可访问）；设置中可改 |
| 保留策略 | 默认保留 7 天，启动时清理过期项；容量上限 500MB（超出提示清理）|
| 通知 | 每次拦截后在工具结果中标注：`⚠ 已拦截 rm → 已移动到回收站（占用路径）` |
| 白名单 | 设置中可添加"信任路径"（如 `/data/local/tmp/`），白名单内 rm 放行为真实删除 |
| 总开关 | 设置 → 安全 → "rm 拦截"（默认**开**）|

### 5.3 解析实现要点
- 简单 `sed` 替换不可靠：需词法级解析（支持 `rm -rf a b c`、`sh -c "..."` 内嵌、`&&` 链）。
- MVP：覆盖 90% 常见形态；解析失败的复杂命令**拒绝执行**并回告 AI "命令包含 rm 但无法安全重写"，让模型改写。
- 回收站管理页：列表 + 恢复（移回原路径）+ 彻底删除 + 清空。

### 5.4 用户可见性
- 侧边栏设置 → 安全 → "回收站"入口，展示拦截历史（时间、原命令、目标路径、大小）。

## 6. 需求六：内置终端 + tmoe 引导（P1 · 大功能）

### 6.1 概述
内置一个**精简版命令行终端**（基于 Termux 开源项目裁剪），并提供与主 UI 风格一致的 **tmoe 引导安装器** 与 **proot/chroot 容器管理**。

### 6.2 终端内核选型
| 方案 | 体积 | 说明 |
|---|---|---|
| **A（选定）**：Termux 精简 bootstrap | 目标 ≤ 6-8MB | 取 termux-app 的 TermuxService/TerminalView（JTDeTeX/Terminal-emulator），只打包核心 bootstrap（busybox toybox 替代部分 coreutils、删 docs/man/locales/groff/perl 等），保留 apt 接口 |
| B：完全自研 PTY 终端 | 最小 | 仅内置 toybox；无包管理，功能弱，不满足 tmoe 依赖 |
| C：完整 Termux | ~15MB | 用户明确认为过大 |

裁剪清单（目标从 ~15MB → ≤8MB）：
- 删除：man 页、示例、python/perl/ruby 默认包、字体冗余、`apt` 的翻译文件
- 替换：coreutils → toybox（保留 bash、apt、curl、tar、proot 依赖链）
- 必留：`bash`、`apt`(dpkg/debian-keyring)、`curl`、`tar`、`proot`（tmoe 必需）、`tzdata`

### 6.3 终端功能
| 功能 | 说明 |
|---|---|
| 终端界面 | TerminalView（Apache-2.0，与 termux-app 同源）；主题跟随 App（毛玻璃工具栏 + 圆角），字号/配色/字体在"终端设置"内调整 |
| 多会话 | 最多 4 个会话，侧滑切换（复用现有侧边栏交互语言）|
| 快捷栏 | 常用键 ESC/TAB/CTRL/上下左右/管道/减号，可自定义按键集 |
| 与按键区联动 | 临时按键区的卡片点击即在当前终端会话执行（需求二）|
| 悬浮终端 | 可选：通知栏快捷入口唤起半屏终端（后期版本）|

### 6.4 tmoe 引导安装器（UI 风格与主 App 完全一致）
tmoe（2dust 的 tmoe-linux / AryaKrimo 的 tmoe）是 proot/chroot 发行版管理脚本。要求：
1. **引导流程原生 UI 化**：首次进入显示"安装 tmoe"向导卡片（介绍 → 磁盘检查 → 下载 → 进度条 → 完成），全部使用 LXSH 毛玻璃卡片风格，而非黑底脚本问答。
2. 交互问答转为原生对话框（选择镜像源、选择是否装 proot 等）。
3. 安装完成后进入"**容器管理**"页：
   - 发行版列表（Ubuntu/Debian/Arch/Alpine…）安装/启动/停止/删除
   - 容器卡片显示：名称、占用空间、上次启动时间
   - VNC/SSH 快捷入口（如容器内配置了）
4. 失败兜底：引导失败时给出"打开原始终端手动继续"按钮。

### 6.5 存储与权限
- root 设备：优先 `/data/local/lxsh-rootfs/`；非 root：App 私有目录 + proot。
- 大文件（rootfs tar）下载支持断点续传。

## 7. 需求七：设置中心重构（P1 · 信息架构）

### 7.1 现状问题
"个性化"、"系统设置"分散在侧边栏一级入口，条目混乱。

### 7.2 新结构
侧边栏一级仅保留：
```
仪表盘 | 分组管理 | 账号管理 | 密钥管理 | 调用日志 | 对话 | 临时按键区 | 终端 | 设置 ▾
```
点击"设置"进入**设置中心**（二级页面），条目排列规范如下：

| 分组 | 条目 |
|---|---|
| **外观** | 主题（浅/深/跟随系统）· 背景与字体 · 圆角与毛玻璃强度 · 动画性能（高刷开关）|
| **对话** | 默认模型 · 流式设置（打字机速度）· 工具调用折叠 · 并行工具上限 · 思考过程默认展开 |
| **Agent 与安全** | rm 拦截 · 回收站管理 · 白名单路径 · 系统提示词 · 最大步数 · root 权限 |
| **终端** | 终端字体/字号/配色 · 快捷键栏自定义 · tmoe 容器管理入口 |
| **临时按键区** | 默认分组 · 执行确认策略 · 导入导出 |
| **个性化** | 现有全部个性化开关（从侧边栏一级移入此处）|
| **系统**（原"系统设置"）| 控制台入口/端口 · GitHub 源码更新 · 关于（版本/许可/开源致谢）· 数据备份与恢复 |

### 7.3 交互
- 设置中心为单页分组列表（右侧滑入二级详情），平板/横屏双栏。
- 搜索设置项（顶部搜索框，拼音/关键词匹配）。
- 每个开关即时生效并持久化（沿 `zako-prefs` → Java `SharedPreferences` 迁移）。
